# 03: 滤波完成与失败契约（D4／审计 #3）

**What to build:** Receiver_Bank 三个滤波入口（批量 void 入口与两个返回滤波数组的重载）具备明确的同步完成与失败契约：正常返回即全部所需滤波已安装；失败向调用方抛出原始异常，不转为后台未观察异常、不发布半成品结果；CreatingFilter 在正常与异常退出后均复位。移除批量入口中无实际异步工作的修饰与死任务代码，保持串行顺序与公共签名。逐一核查同步反序列化、结果重建、声源编辑、Hybrid 和 Mapping 调用场景：同步调用直接观察失败；后台 UI 调用等待其 Task 并经现有错误展示路径报告、清理进度状态。

**Blocked by:** 01（断言工程承载 T4 断言）

**Status:** ready-for-agent

- [ ] 批量 void 入口保留公共签名与串行顺序；正常返回意味着全部滤波已安装；移除多余 async 修饰与死任务代码
- [ ] 失败向调用方抛出原始失败；正常/异常退出均复位 CreatingFilter；失败不发布新完成结果
- [ ] 两个返回数组的重载保留签名与返回值语义；运算结束后返回、传播失败、正常/异常退出后复位 CreatingFilter
- [ ] 同步调用方直接观察失败；后台 UI 调用等待其 Task、经现有错误路径报告并清理进度窗口与处理标志
- [ ] T4 断言通过：三个入口的可控失败均可被调用者观察；批量后台调用的失败可由 await 观察；各入口失败后 CreatingFilter 复位
- [ ] 进度反馈沿用现有 UI 调度方式；FFT 槽位策略与滤波算法不变；不做接收器并行
